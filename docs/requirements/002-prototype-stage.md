# 原型设计阶段

用户确认的顺序：需求澄清 → 原型设计 → 技术方案 → 开发 → 本地验证 → 提交。

## 需求与实现

- 已有项目：参考隔离副本中的现有页面和样式，可补充页面路径、修改说明及 PNG/JPEG 截图；生成体现新需求的 SVG 原型，不改业务代码。
- 全新项目：只需名称即可建档，无需仓库；基于已确认需求和设计偏好生成原型。开发前绑定有首个提交的本地 Git 仓库，并结合仓库重新确认方案。
- 原型支持预览、下载、修改输入后重新生成和版本确认。确认之前不能生成技术方案。
- 原型输入变化后，旧版本保留但不可直接确认；确认版本写入后续方案和开发上下文。
- 历史任务保持已到达阶段，不因新增步骤被强制退回。

## 验证

新增门禁、全新项目绑定、版本失效、失败重试、持久化、绘图数据校验等集成测试；模型调用仍使用测试替身，原有真实 Git 流程继续测试。运行 `npm run check` 验证。静态图不等同于交互或视觉验收；本轮不实现前面讨论的视觉对比 MCP。
