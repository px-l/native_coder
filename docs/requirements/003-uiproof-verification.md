# UIProof MCP 页面验收

流程为需求澄清 → 原型设计 → 技术方案 → 开发 → 本地验证 → 提交。本地验证同时执行项目检查和独立的 UIProof MCP 验收；任一失败、超时或连接错误都不得提交。

工作台仅保存调用适配代码。UIProof 的截图、比较、报告及服务器部署代码属于 `px-l/UIProof-MCP`，不得复制进本仓库。kedian 等业务仓库仍保持原有写入授权边界。

验收基准固定为任务已确认原型，视口来自原型画布。用户在当前任务的工作副本启动测试页面，填写本地预览地址；服务器通过仅绑定 loopback 的临时 SSH 反向隧道访问页面，任务结束时关闭隧道。页面使用同源 API 代理；直接访问本机其他端口的绝对 URL 需在业务测试环境配置代理后验收。

原型 SVG、页面及报告会进入操作者指定服务器，使用测试数据。MCP 通过现有 SSH 密钥认证，不新增公开 HTTP 端口、不在浏览器保存凭据。生产部署及远程模型分析不包含在工作台验证动作内。

通过结果同时绑定 Git tree、原型版本及内容哈希、目标地址、就绪条件。验证期间代码变化、重新开发或修改验收地址后必须重新验证。历史没有原型的任务保留旧流程；历史仍未提交且有原型的任务补充此门禁。

UIProof 不能仅凭 URL 证明某个进程确实运行指定工作副本。用户必须从显示的任务副本启动服务；工作台绑定 tree 并检查验证期间没有代码变化，但不声称证明远程页面代码来源。已有截图基准与 Linux 字体可能产生差异，报告应由产品/开发人员审阅，不自动放宽阈值或更改基准。

报告通过已验证会话下载为独立 HTML，不在工作台主页面直接执行远端 HTML。
