# Native Coder 首版需求

状态：用户已确认独立工作台与业务仓库分离；本轮不修改 kedian，不部署。

## 用户与目标

面向开发人员和产品经理，完成从原始需求到代码生成、本地验证、提交业务仓库的流程。

- 工作台代码提交至 `git@github.com:px-l/native_coder.git`。
- kedian-monorepo 是接入的业务项目，现有远端为 `git@github.com:p3psi-boo/kedian-monorepo.git`。
- 当前 kedian 只读；通过临时测试仓库验证写入和推送能力。

## 功能与验收

| 编号  | 功能         | 验收标准                                                         |
| ----- | ------------ | ---------------------------------------------------------------- |
| AC-01 | 接入业务仓库 | 读取本地 Git 根目录和 origin，默认只读，显示检查命令             |
| AC-02 | 需求澄清     | 保存原始需求、生成或编辑需求说明与验收标准，确认后进入方案       |
| AC-03 | 技术方案     | 结合隔离副本中的代码生成方案，人工确认后才能开发                 |
| AC-04 | 开发         | 调用本机 Codex CLI，仅在独立 clone 内修改代码；只读项目禁止执行  |
| AC-05 | 本地验证     | 执行真实检查，展示逐项通过/失败和输出；失败不能提交              |
| AC-06 | 差异评审     | 展示新增、修改、删除文件的 Git 差异与目标分支                    |
| AC-07 | 代码提交     | 验证树一致后创建本地提交，返回真实提交标识                       |
| AC-08 | 远端推送     | 单独推送业务仓库任务分支，失败不显示成功，不强推或合并           |
| AC-09 | 持久化       | 重启后恢复任务、文档和结果；中断的执行标记失败                   |
| AC-10 | 保护 kedian  | 只读配置由后端执行，不能绕过界面触发开发、安装、检查、提交或推送 |

## 非目标

本轮不提供多人权限系统、部署、自动 PR/合并、远程仓库发现或业务项目代码改造。
